# AoE4 儀表板資料格式（version 1）

儀表板 `index.html` 讀取一個 JSON 物件。之後寫 API 程式時，只要產生這個格式即可，有三種接法：

1. **覆寫檔案**：寫入 `data/aoe4-data.js`，內容為 `window.AOE4_DATA = { ...JSON... };`，重新整理網頁即可。
2. **API 網址**：在 `index.html` 上方把 `AOE4_CONFIG.dataUrl` 設成 API 網址（回傳純 JSON），`refreshMinutes` 設定自動更新間隔。網頁是用檔案開啟時，API 伺服器要回傳 `Access-Control-Allow-Origin: *`。
3. **手動匯入**：網頁右上角「匯入資料」選 `.json` 或 `.js`，或直接拖進視窗。

另外網頁提供 `window.AOE4Dashboard.load(資料)`，可由其他程式碼直接推送資料。

## 從 aoe4world 取得資料（給之後的 API 程式參考）

| 用途 | 網址 |
|---|---|
| 玩家資料與目前分數 | `https://aoe4world.com/api/v0/players/{profile_id}` |
| 對局清單（每頁 50 場，依 `next_page` 翻頁） | `https://aoe4world.com/api/v0/players/{profile_id}/games?limit=50&page=1` |
| 單場詳細摘要（逐時數據） | `https://aoe4world.com/players/{profile_id}/games/{game_id}/summary?camelize=true` |

- 對局清單的 `teams` 是 `[[{player:{...}}]]`，每位玩家包在 `player` 裡。
- 摘要不需要 API key；自訂對局通常回傳 404。
- `villagers`、`army` 由摘要的 `buildOrder`（每種單位的 `finished`／`destroyed` 時間）推算存活數量；`army` 不含村民、偵察兵、僧侶、商人與漁船。
- 舊版摘要沒有 `*Gathered` 欄位，可用 `*PerMin` 以梯形法積分估算，並把 `gatheredEstimated` 設為 true。

## `*Gathered` 的意思

- aoe4world 新版摘要的 `resources.*Gathered` 雖然叫 Gathered，實際上是**累積花費**：最後一筆等於 `totalResourcesSpent`。所以 `source` 不是 `local-replay`、而且 `gatheredEstimated` 為 false 的玩家，`*Gathered` 是累積花費。
- `gatheredEstimated` 為 true（舊版摘要）或 `source` 為 `local-replay` 的玩家，`*Gathered` 是由採集速率推算的累積採集量。
- 儀表板會換算成兩條曲線：累積採集 = 花費 + 庫存變化，累積花費 = 採集 − 庫存變化。

## 建造事件與資源利用分析

- `events` 和 `catalog` 由 `node enrich-summaries.js` 補上：從 aoe4world 摘要的 `buildOrder` 取出每個項目的完成、蓋好和被摧毀時間，摘要快取在 `data/summaries/`，成本表取自 `data.aoe4world.com`，快取在 `data/catalog/`。
- 本機重播的 `events` 由 `lib/local-detail.js` 從 `stats.rgs` 的 `unitTimeline` 產生，種類代碼的對照照 aoe4world replays-api 的 `CompatConverter`。
- 單場分析的「資源利用」用這些資料算出囤積、佇列呆料、生產建築利用率；沒有 `events` 的場次只會顯示囤積。
- `orders` 由 `node enrich-replays.js` 補上：從官方統計網站下載重播（`api.ageofempires.com/api/GameStats/AgeIV/GetMatchReplay/?gameId=…&profileId=…`，玩家要開啟分享對戰紀錄，舊重播會過期，快取在 `data/replays/`），用 `lib/rec-parse.js` 取出訓練與研究指令。也可以用 `--file 對局id=重播檔路徑` 指定本機的重播檔。有 `orders` 的場次，佇列呆料改用逐棟模擬：重播只記錄指令、不記錄佇列，所以照遊戲規則重演——每個訓練／研究指令排進那棟建築一項（下指令時扣款）、取消指令照項目序號移除（每棟建築的訓練／研究指令依序從 1 編號）、同一棟先進先出；每一項的完成時間優先用 `events` 的完成事件校正，沒有完成紀錄的才用成本表的生產時間推算。到對局結束都沒做完的項目（人口已滿、建築被拆）會一直算在佇列裡。`detail.ordersVersion` 是 orders 的格式版本（2 = 含取消指令），版本較舊的場次重跑 `enrich-replays.js` 會用快取的重播重新產生。
- 每個請求之間間隔 1 秒以上，已下載的摘要存起來不要重複抓。

## 看別人的戰績（網頁裡直接組資料）

儀表板的「看別人的戰績」不經過上面的同步程式，而是在訪客的瀏覽器裡組出同樣格式的資料：

- `js/aoe4world.js`：向 AoE4 World 搜尋玩家、讀對局清單（最多最近 1000 場）、把單場摘要轉成 `detail`（轉換規則和現有資料完全相同，已用 `data/summaries/` 的 47 場逐欄比對過），再向官方戰績網站下載重播檔補上 `orders`。
- `js/rec-parse.js`：重播檔解析，Node 的 `lib/rec-parse.js` 也是用這一份。
- `catalog.json`：完整成本表（`node build-dashboard-catalog.js` 產生，遊戲改版後加 `--refresh` 重跑）。
- 單場摘要不允許其他網站直接呼叫，所以網頁改打同網域的 `/proxy/summary/玩家ID/對局ID`，由 `aoe4-frontend/worker/index.js`（Cloudflare Worker）轉接並快取；`npm run dev` 時由 `vite.config.ts` 轉接。
- 對局清單和下載過的單場資料存在訪客瀏覽器的 IndexedDB（`aoe4-dashboard`），下次只抓新的對局。網址 `?player=玩家ID` 可以直接分享。
- 重播檔只有最近一段時間的對局拿得到（較舊的回 404），玩家也要在遊戲裡開啟分享對戰紀錄；拿不到重播的場次，佇列呆料改用資源流量推估。
